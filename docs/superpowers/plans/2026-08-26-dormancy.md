# Dormancy (admission policy) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop spending 90% of every sweep on 57 endpoints that have never answered, without ever presenting a stale verdict as a fresh one, on any route or in any representation.

**Architecture:** A pure decision module (`prober/src/dormancy.rs`) holds the policy. A machine-written TOML state file holds strikes, last-probed instants and operator holds; the sweep reads it to decide what to probe and, at the end, re-reads it under a short lock and applies its outcomes to what is on disk then. Each sweep publishes, in a dedicated section of its own run graph, which endpoints it did not probe and why. **The web tier stores no derived dormancy at all**: staleness is a comparison between the run a verdict came from and the newest run in the store, which both read queries already compute, and dormancy is the newest run's own fact supplying the reason.

**Tech Stack:** Rust (serde, toml, clap 4), Python 3.12 (pyoxigraph 0.5.9, FastAPI, jinja2), pytest, cargo test.

**Spec:** `docs/superpowers/specs/2026-08-19-sparql-endpoint-monitor-design.md`, section **Admission policy: dormancy**.

## Revision history, and the one thing to read before anything else

Three drafts, four reviews, eighteen Criticals. Revision 1 was reviewed twice (8 Criticals) and revision 2 was reviewed twice (10 Criticals). **Revision 3 is smaller than revision 2**, and that is the point: revision 2's ten Criticals were concentrated in the machinery revision 1 had ADDED, and a third of them came from one mechanism. Notes marked **REVIEW** record a decision that changed, so nobody reinstates it.

**The mechanism that is gone: there is no `sw:currentDormancyRun` pointer and no dormancy in the `current` graph.** Revision 2 gave dormancy its own recency pointer in `current`, wired into `_advance`, `_pointers`, both drift checks, `pointers_to_missing_runs`, `_FACTS_FOR_ENDPOINT` and a specified rebuild ordering. That produced four Criticals on its own: `rebuild_current` would re-mark the whole dormant cohort on its probe day because dormancy's independent recency disagreed with the measured recency; re-loading a run, which `load_run.py:9-18` documents as the recovery, would delete a newer run's dormancy with nothing able to detect it; and widening the single shared `_FACTS_FOR_ENDPOINT` template would make `--check` report every dormant endpoint as drift and exit 1 over a correct store.

The replacement needs no stored state. **Staleness is already computable**: `endpoint_measurements.rq:250-257` and `index.rq:197-200` already bind `?newestRun`, `?newestGeneratedAt`, `?newestFinalised` and `?newestCompleted`. An endpoint whose verdicts came from a run other than the newest, where the newest run FINISHED and does not name the endpoint in `sw:completedEndpoint`, has stale verdicts, and that is true whatever the reason. Dormancy is then read from the newest run graph by exactly the pattern `?newestCompleted` already uses, as a REASON clause on a claim that stands without it.

Three things fall out of that, all good:

1. **Clearing becomes automatic.** On its probe week the endpoint is measured, `sw:currentRun` advances, that run carries no dormancy fact for it, and the marker is gone with no clearing rule, no ordering rule, and no conditional delete.
2. **`load_run.py` barely changes.** No pointer, no template widening, no rebuild ordering, no new drift check. A dormant endpoint has no measurements, so it is absent from `measured` and `sampled` and `current` is correct for it by construction.
3. **The fix is general.** Which matters, because the reviews found the same defect already live: `~/code/sparqlwatch-runs/` holds `run-2026-08-24T20-00-00Z-calibration-54.nq`, a FINISHED 54-endpoint run fifteen minutes NEWER than the 543-endpoint sweep. Loading it into `store.db`, one documented command, makes 489 endpoint pages read "Everything below is what one probe sweep observed, at 2026-08-24T19:45:03Z" with no qualifier while the newest sweep in the store finished later and never asked them. That is a false claim on this site today, and the general property is what fixes it.

## Global Constraints

- **No em-dashes anywhere**: code, comments, doc text, commit messages, template copy.
- **The six-verdict vocabulary is closed.** Dormancy is not a verdict.
- **A positive verdict is `Verified` or `UndeclaredButVerified`, and nothing else.**
- **`MeasurementRow::elapsed_ms == None` contributes ZERO cost.** REVIEW, reversing revision 1. `None` has three producers and only one spent time: the endpoint-budget fill (`lib.rs:566`) and an unimplemented probe kind (`lib.rs:668`) cost nothing; only metric-budget expiry (`lib.rs:750`) cost 60 s. Attributing 60 s to all three means one future metric shipped without a probe gives every endpoint in the registry phantom cost and relegates all 459 silent ones, which is the failure-weighted policy the spec rejects. Counting zero is safe where it looks dangerous: an endpoint that blew the 600 s `Budget::endpoint` accumulated roughly 600 s of REAL elapsed in the metrics that ran.
- **TWO TIME GRANULARITIES, deliberately, and they must not be unified.** Idempotence compares **exact instants**, because two sweeps in one day are two sweeps and a re-run reuses its `--at`. The cadence compares **whole days**, because a sweep fifteen minutes early is not a day early. An implementer who unifies them reintroduces one bug or the other; both are described where they are used.
- **`--at` is narrowed to UTC.** REVIEW: revision 2 claimed the dormancy helper accepts "what `validate_instant` already requires". That was false: `validate_instant` accepts `2026-08-20T12:00:00+02:00`, `-05:00`, fractional seconds and the leap second `23:59:60`, and `prober/README.md:74` documents `--at` as "ISO-8601 with an explicit timezone". A strict helper would then refuse an `--at` the prober documents as valid, after `validate_instant` passed it, and could write a state file it later refuses to parse. This stage narrows `--at` to `...Z`, with optional fractional seconds truncated, because the run instant is now an identifier, a sort key AND the input to day arithmetic, and three lexical forms for one instant make all three ambiguous. It changes a documented flag: `README.md:74` and `validate_instant`'s own test move with it.
- **The sweep never prunes state.** REVIEW: revision 2 dropped state entries for endpoints absent from `--endpoints`. The spec itself documents a narrowed sweep (it is how the 57 were re-probed), so `--endpoints just-the-57.toml` would have destroyed the other 486 entries, lost the dormant set, and cost the full 3.12 h to rebuild. Pruning is an explicit `dormancy prune` that prints what it drops.
- **An operator hold overrides the machine in both directions**, and a command issued during a 90 minute sweep must survive that sweep's write-back.
- **Never `git add -A`.** Stage by name.
- **Tests must not probe network endpoints.**
- **Commit messages end with:** `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- Defaults: cost `> 60_000` ms, `2` strikes, cadence `7` days, grace `7` days. All four are flags and all four are validated at startup, **including the cost**, which revision 2 left as a bare `u64`: `--dormant-cost-ms 60`, seconds typed where the flag takes milliseconds, relegates roughly 460 endpoints. The floor is 30_000, because a single `Budget::request` is 30 s and a threshold at or below that cannot tell silence from cost.

```rust
pub const DEFAULT_COST_MS: u64 = 60_000;
pub const MIN_COST_MS: u64 = 30_000;       // one Budget::request
pub const DEFAULT_STRIKES: u32 = 2;
pub const DEFAULT_CADENCE_DAYS: u64 = 7;
pub const DEFAULT_GRACE_DAYS: u64 = 7;
pub const STATE_VERSION: u32 = 1;

pub struct Thresholds {
    pub cost_ms: u64,                 // validated >= MIN_COST_MS by main.rs
    pub strikes: NonZeroU32,
    pub cadence_days: NonZeroU64,
    pub grace_days: NonZeroU64,
}

/// `Dormant` carries no expiry, so a hold the policy ignores cannot exist and
/// a malformed expiry on one cannot go undetected.
pub enum Hold {
    Awake { reason: String, until: Option<String> },
    Dormant { reason: String },
}

pub struct EndpointState {
    pub url: String,
    pub strikes: u32,
    /// Strikes as of the instant BEFORE `last_probed`. What makes a re-run of
    /// one `--at` exact rather than merely harmless: a replay recomputes from
    /// here instead of incrementing `strikes` again, so a replay whose outcome
    /// DIFFERS (the endpoint answered this time) still promotes.
    pub strikes_before_last: u32,
    pub last_probed: Option<String>,
    pub last_cost_ms: Option<u64>,
    /// Since when has this endpoint not been probed, whoever decided it.
    /// `sleep` sets it if it is not already set, preserving the original
    /// relegation instant that a run graph has already published.
    pub dormant_since: Option<String>,
    pub hold: Option<Hold>,
    /// A lapsed `Awake` hold's reason, so `list` can still say a person
    /// intervened and that it ran out.
    pub lapsed_hold: Option<String>,
}

pub struct State { pub version: u32, pub updated_at: Option<String>, pub endpoint: Vec<EndpointState> }
impl State {
    pub fn empty() -> State;
    /// Validates `version` AND every instant-shaped field, naming the field.
    /// Refuses `dormant_since` set with `last_probed` absent, which the header
    /// comment invites a human to create and rule 4 cannot evaluate.
    pub fn parse(toml_text: &str) -> anyhow::Result<State>;
    pub fn render(&self) -> String;
    pub fn get(&self, url: &str) -> Option<&EndpointState>;
}

pub enum SkipReason { Automatic, OperatorHold }
pub struct Skipped { pub url: String, pub dormant_since: Option<String>, pub reason: SkipReason }
pub struct Plan { pub probe: Vec<String>, pub skipped: Vec<Skipped> }

pub fn plan_sweep(state: &State, endpoints: &[String], now: &str, thresholds: &Thresholds)
    -> anyhow::Result<Plan>;
pub struct Outcome { pub url: String, pub cost_ms: u64, pub positive: bool }
pub fn update(state: &State, endpoints: &[String], outcomes: &[Outcome], now: &str,
              thresholds: &Thresholds) -> anyhow::Result<State>;
pub fn wake(state: &State, url: &str, reason: &str, now: &str, permanent: bool,
            thresholds: &Thresholds) -> anyhow::Result<State>;
pub fn sleep(state: &State, url: &str, reason: &str, now: &str) -> anyhow::Result<State>;
/// Entries whose url is not in `endpoints` and which carry no live hold, and
/// the state without them. Called ONLY by `dormancy prune`, never by a sweep.
pub fn prunable(state: &State, endpoints: &[String]) -> (Vec<String>, State);
```

**`plan_sweep`, per endpoint, in order:**

0. **`last_probed == now`, compared as exact strings: PROBE.** REVIEW, and this is revision 3's most important single line. Without it the documented recovery destroys data, not just state. A sweep at `--at D` probes E and records `last_probed = D`; the operator re-runs `--at D`; rule 4 computes `day(D) - day(D) = 0 >= 7`, false, so E is SKIPPED; the re-run's file is renamed onto `--out`, and loading it REPLACES run graph D, so every measurement the first run made for E is gone and replaced by a dormancy fact. On the first relegation sweep that is all 57 at once, and `current` then points at a run that no longer states their facts. Forcing a probe on an exact-instant match makes a re-run reproduce the same probe set, which is what "re-run the same `--at`" has to mean.
1. `hold` is `Dormant`: SKIP, `OperatorHold`, carrying `dormant_since`.
2. `hold` is `Awake` and (`until` is `None` or `day(until) >= day(now)`): PROBE.
3. `dormant_since` is `None`: PROBE.
4. `dormant_since` is set: PROBE if `day(now) - day(last_probed) >= cadence_days` AND the endpoint is in the oldest `slice` of the due set. Otherwise SKIP, `Automatic`.

`slice = ceil(governed / cadence_days)`, at least 1, where `governed` counts only endpoints rule 4 reaches: in `endpoints`, `dormant_since` set, no effective hold. REVIEW: counting every entry with `dormant_since` inflates it, because strikes accumulate under a hold by design, so 57 automatic plus 100 pinned-awake gives `ceil(157/7) = 23` and rotates the real set in three days instead of seven. Order the due set by `last_probed` ascending then `url`; a due-but-unsliced endpoint keeps its old `last_probed`, sorts ahead of everything probed since, and climbs into the next slice, so it cannot starve.

**`update`:**

Rule A runs for **every entry in the state**, including entries whose url is not in `endpoints`. REVIEW: revision 2 scoped lapse-clearing to endpoints in the list, which is exactly the case it was added for, so a hold on a dropped url stayed live forever and kept the entry immortal.

- **A. Clear a lapsed `Awake` hold.** If `hold` is `Awake { until: Some(u) }` and `day(u) < day(now)`: `hold = None`, `lapsed_hold = Some(reason)`, **and `strikes = 0`**. REVIEW: the spec (`:712-715`) says a wake makes an endpoint "immune from automatic relegation for seven days". Revision 2 let strikes accumulate through the grace and relegate on the day after it lapsed, so a wake bought seven days of probing and then instant re-relegation on evidence gathered while the endpoint was supposed to be immune. Resetting at the lapse means relegation costs two post-grace sweeps, which is what immunity means and what the spec says.

Then, per endpoint in `endpoints`:

- **B. Replay.** `last_probed == now` exactly: recompute from `strikes_before_last` rather than `strikes`, leaving `strikes_before_last` alone. A replay is therefore exact: same outcome gives the same strikes, a better outcome promotes.
- **C. Out of order.** `last_probed` is present and `now < last_probed` as an instant: carry forward unchanged, and log. An older sweep must not move state backwards, for the same reason `_advance` will not move `current` backwards.
- **D. Not in `outcomes`:** carry forward unchanged.
- **E. Positive:** `strikes_before_last = strikes`, `strikes = 0`, `dormant_since = None`, `last_probed = now`, `last_cost_ms = Some(cost)`.
- **F. Not positive, `cost_ms >` threshold:** `strikes_before_last = strikes`, `strikes += 1`, `last_probed = now`, `last_cost_ms = Some(cost)`; if `strikes >=` the strike threshold and `dormant_since` is `None`, `dormant_since = Some(now)`.
- **G. Not positive, cost at or under:** `strikes_before_last = strikes`, `strikes = 0`, `last_probed = now`, `last_cost_ms = Some(cost)`, `dormant_since` unchanged.
- **H.** A `Dormant` hold means no outcome ever exists, so E to G cannot fire for one. An `Awake` hold does not suppress them.
- **I.** Duplicate urls in `outcomes` are an error.
- **NO PRUNING.** Entries not in `endpoints` keep their state.

**The instant helper.** Private, pure, no date dependency. Accepts exactly `YYYY-MM-DDTHH:MM:SS[.fff]Z`, truncating any fraction, and yields a proleptic Gregorian day number. `main.rs` validates `--at` against the same grammar at startup (see Task 3), so `plan_sweep` never fails on a value `validate_instant` waved through. Own tests: a leap day (`2028-02-29`), a year boundary, a fractional second, a rejected offset, and the early-start case.

```rust
fn a_wake_is_immune_from_relegation_and_not_merely_from_skipping() {
    // The spec says immune from automatic relegation for seven days. Letting
    // strikes stand at the lapse means the wake buys seven days of probing and
    // then instant re-relegation on evidence gathered during the immunity.
    let endpoints = vec![ep("http://a.example/s")];
    let t = Thresholds::default();

        state = update(&state, &endpoints, &[expensive("http://a.example/s")], day, &t).unwrap();

}
```

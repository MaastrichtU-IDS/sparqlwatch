# Dormancy (admission policy) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop spending 90% of every sweep on 57 endpoints that have never answered, without ever presenting a stale verdict as a fresh one, on any route or in any representation.

**Architecture:** A pure decision module (`prober/src/dormancy.rs`) holds the policy. A machine-written TOML state file holds strikes, last-probed instants and operator holds; the sweep reads it to decide what to probe and, at the end, re-reads it under a short lock and applies its outcomes to what is on disk then. The set of skipped endpoints goes into `RunHeader`, so every run graph publishes what it declined to ask as a matter of construction. The web tier stores no derived dormancy: staleness is a comparison the read queries already compute, and dormancy is the newest run's own fact supplying the reason.

**Tech Stack:** Rust (serde, toml, clap 4), Python 3.12 (pyoxigraph 0.5.9, FastAPI, jinja2), pytest, cargo test.

**Spec:** `docs/superpowers/specs/2026-08-19-sparql-endpoint-monitor-design.md`, section **Admission policy: dormancy**.

## Global Constraints

- **No em-dashes anywhere**: code, comments, doc text, commit messages, template copy.
- **The six-verdict vocabulary is closed.** Dormancy is not a verdict.
- **A positive verdict is `Verified` or `UndeclaredButVerified`, and nothing else.**
- **`MeasurementRow::elapsed_ms == None` contributes ZERO cost.** REVIEW, reversing revision 1. Three producers, only one spent time: the endpoint-budget fill (`lib.rs:566`) and an unimplemented probe kind (`lib.rs:668`) cost nothing; only metric-budget expiry (`lib.rs:750`) cost 60 s. Attributing 60 s to all three means one future metric shipped without a probe gives every endpoint phantom cost and relegates all 459 silent ones, which is the failure-weighted policy the spec rejects. Counting zero is safe where it looks dangerous: an endpoint that blew the 600 s `Budget::endpoint` accumulated roughly 600 s of REAL elapsed in the metrics that ran.
- **Cost is the sum of per-metric `elapsed_ms` for one endpoint in one run.** The quantity the 60 s threshold was calibrated against.
- **TWO TIME GRANULARITIES, deliberately, and they must not be unified.** Replay detection compares **exact instant strings**, because a re-run reuses its `--at` and two sweeps in one day are two sweeps. The cadence compares **whole days**, because a sweep fifteen minutes early is not a day early.
- **`--at` is narrowed to exactly `YYYY-MM-DDTHH:MM:SSZ`.** REVIEW: `validate_instant` accepts offsets (`+02:00`, `-05:00`), fractional seconds and the leap second `23:59:60`, and `README.md:74` documents "ISO-8601 with an explicit timezone". A strict helper would refuse an `--at` the prober documents as valid. **No fractional seconds either**: replay detection compares instants as strings, so `...00Z` and `...00.000Z` would be one instant, two run IRIs and no replay match, defeating the narrowing's whole purpose. **The leap second is refused too**, and that is a deliberate loss: `main.rs:314` currently pins `2026-12-31T23:59:60Z` as valid, and a day-number helper cannot place second 60. `README.md:74` and the test at `main.rs:310-321` move with the change.
- **The sweep never prunes state.** REVIEW: the spec documents a narrowed sweep (it is how the 57 were re-probed), so `--endpoints just-the-57.toml` would have destroyed the other 486 entries. Pruning is an explicit `dormancy prune`.
- **An operator hold overrides the machine in both directions**, including over replay detection, and a command issued during a 90 minute sweep must survive that sweep's write-back.
- **Never `git add -A`.** Every task's Step 5 lists its files explicitly.
- **Tests must not probe network endpoints.**
- **Commit messages end with:** `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- Defaults: cost `> 60_000` ms (floor `30_000`, one `Budget::request`), `2` strikes, cadence `7` days, grace `7` days. All four are flags, all four validated at startup.

**`wake` and `sleep`, written out.** REVIEW: revision 3 declared their signatures, wrote tests around them, and never said what they do. An implementer had to infer the grace arithmetic from a test comment.

- `wake(state, url, reason, now, permanent, thresholds)`: upsert the entry (an unknown url gains one, because an operator may know something before the machine does). Set `hold = Awake { reason, until }` where `until` is `None` when `permanent`, else the instant `grace_days` after `now`, rendered in the same `YYYY-MM-DDTHH:MM:SSZ` form with `now`'s time of day preserved. **Set `strikes = 0`, `strikes_before_last = 0` and `dormant_since = None`**, because the spec (`:712-715`) grants immunity from relegation and an endpoint that stays relegated is not immune. Leave `last_probed` and `last_cost_ms` alone. Clear `lapsed_hold`. Set `updated_at = now`.
- `sleep(state, url, reason, now)`: upsert; set `hold = Dormant { reason }`; set `dormant_since = Some(now)` **only if it is not already set**, preserving the original relegation instant that a run graph has already published. Leave strikes alone. Set `updated_at = now`.

**`plan_sweep`, per endpoint, IN THIS ORDER:**

1. **`hold` is `Dormant`: SKIP, `OperatorHold`**, carrying `dormant_since` as it stands. REVIEW: this precedes replay detection. Revision 3 put replay first, so a re-run of an `--at` from before an operator's `sleep` would have probed an endpoint a person forbade, against the Global Constraint that a hold overrides the machine in both directions.
2. **Replay: `this_at_has_already_run` and `last_probed == now`: PROBE.** Where `this_at_has_already_run` is computed ONCE for the whole sweep as "any entry in `endpoints` has `last_probed == now`". REVIEW: revision 3 tested this per endpoint, which reproduces only half a replay. With 57 dormant, cadence 7 and a slice of 9, the first run probes the 9 oldest and moves their `last_probed`; a re-run then probes those 9 by rule 2 AND admits the next 9 through rule 5, so it probes **18, not 9**, spends roughly 31 extra minutes, and writes a run graph that disagrees with the first about what it skipped. Globally: if this `--at` has already run, probe exactly the entries it probed and skip everything else. This is sound because state is written only after the footer, so a crashed run leaves no replay marker and its re-run is correctly a fresh sweep.
3. **`this_at_has_already_run` and `last_probed != now`: SKIP, `Automatic`.** The other half of rule 2.
4. `hold` is `Awake` and (`until` is `None` or `day(until) >= day(now)`): PROBE.
5. `dormant_since` is `None`: PROBE.
6. `dormant_since` is set: PROBE if `day(now) - day(last_probed) >= cadence_days` AND the endpoint is in the oldest `slice` of the due set; else SKIP, `Automatic`.

**The slice, and why it is not a constant fraction.** REVIEW: revision 3 used `ceil(governed / cadence_days)`, which silently assumes one sweep per day. Nothing here is on a schedule (`test_about.py:530-561` pins that the page says so), and a 1h26m sweep run weekly would probe 9 of 57 per sweep, giving each dormant endpoint a probe every 6.3 weeks against spec rule 2's seven days. The divisor must come from the observed gap:

```
gap  = max(1, day(now) - day(state.updated_at))      // 1 when updated_at is absent
slice = clamp(ceil(governed * gap / cadence_days), 1, governed)
```

Daily sweeps give `ceil(57 * 1 / 7) = 9`; weekly sweeps give `57`, so a week's worth is probed in the sweep that a week has passed before. `governed` counts only endpoints rule 6 reaches: in `endpoints`, `dormant_since` set, no effective hold. Order the due set by `last_probed` ascending then `url`. A due-but-unsliced endpoint keeps its old `last_probed`, sorts ahead of everything probed since, and climbs into the next slice, so it cannot starve.

**`update`:**

Rule A runs for **every entry in the state**, including entries whose url is not in `endpoints`.

- **A. Clear a lapsed `Awake` hold.** If `hold` is `Awake { until: Some(u) }` and `day(u) < day(now)`: `hold = None`, `lapsed_hold = Some(reason)`, **`strikes = 0` and `strikes_before_last = 0`**. REVIEW: revision 3 cleared only `strikes`, so a replay of the last grace-period sweep after the lapse recomputed from `strikes_before_last = 1` and re-relegated immediately.

Then, per endpoint in `endpoints`:

- **B. Replay.** `last_probed == now` exactly: recompute from `strikes_before_last`, leaving `strikes_before_last` unchanged.
- **C. Out of order.** `last_probed` present and `now < last_probed`: carry forward unchanged, and log.
- **D. Not in `outcomes`:** carry forward unchanged.
- **E. Positive:** `strikes_before_last = strikes`, `strikes = 0`, `dormant_since = None`, `last_probed = now`, `last_cost_ms = Some(cost)`.
- **F. Not positive, cost above the threshold:** `strikes_before_last = strikes`, `strikes += 1`, `last_probed = now`, `last_cost_ms = Some(cost)`; and if `strikes >=` the threshold and `dormant_since` is `None` **and the entry carries no live `Awake` hold**, set `dormant_since = Some(now)`.
- **G. Not positive, cost at or under:** `strikes_before_last = strikes`, `strikes = 0`, `last_probed = now`, `last_cost_ms = Some(cost)`, `dormant_since` unchanged.
- **H.** A `Dormant` hold means no outcome exists, so E to G cannot fire for one.
- **I.** Duplicate urls in `outcomes` are an error.
- **NO PRUNING.**

**Why rule F has that fourth condition.** REVIEW, and both reviews of revision 3 found it. The spec says a wake "makes it immune from automatic relegation for seven days". Revision 3 let rule F relegate during the grace and had rule A clear only the strikes afterwards, so a woken endpoint was marked dormant on day two of its own immunity and the plan's own test asserting otherwise could not pass. Two fixes were available and they differ: clearing `dormant_since` at the lapse relegates and then un-relegates, while suppressing rule F keeps the endpoint out of the dormant set throughout. **Suppressing is chosen**, because a dormant endpoint counts toward `governed` and toward the published `sw:dormantCount`, and an immune endpoint should appear in neither. Strikes still accumulate underneath, so at the lapse rule A resets them and relegation costs two fresh post-grace sweeps.

**`State::parse`** validates `version` and every instant-shaped field, naming the field and the value. It refuses `dormant_since` set with `last_probed` absent **unless the entry carries a `Dormant` hold**. REVIEW: revision 3 refused that combination unconditionally, and `sleep` on a never-probed endpoint produces exactly it, so one operator command wrote a file the next `read_state` refuses, and `read_state` runs before any probing: **`dormancy sleep` on a new url would have bricked every subsequent sweep and every subsequent `dormancy` command** until a human hand-edited the file. The exemption is safe because rule 1 fires first for a held entry and rule 6, the only reader of `last_probed`, is never reached.

**The instant helper.** Private, pure, no date dependency. Accepts exactly `YYYY-MM-DDTHH:MM:SSZ`: no offset, **no fractional seconds** (two lexical forms for one instant would break the string-equality replay test), and no leap second (a day-number helper cannot place second 60). Yields a proleptic Gregorian day number. Own tests: a leap day (`2028-02-29`), a year boundary, a rejected offset, a rejected fraction, a rejected leap second, and the early-start case from rule 6.

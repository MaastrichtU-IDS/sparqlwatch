# Dormancy (admission policy) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop spending 90% of every sweep on 57 endpoints that have never answered, without ever silently presenting a stale verdict as a fresh one.

**Architecture:** A pure decision module (`prober/src/dormancy.rs`) holds the policy and owns a machine-written TOML state file: strikes, last-probed instants and operator holds. `main.rs` reads the state before probing, asks it which endpoints to probe this sweep, and writes it back atomically after the run footer. Each sweep publishes, in its own run graph, which endpoints it did not probe and why. The web tier copies those facts into the derived `current` graph additively, and every page that shows a verdict says how old that verdict is.

**Tech Stack:** Rust (serde, toml, clap 4), Python 3.12 (pyoxigraph 0.5.9, FastAPI, jinja2), pytest, cargo test.

**Spec:** `docs/superpowers/specs/2026-08-19-sparql-endpoint-monitor-design.md`, section **Admission policy: dormancy**. That section carries the measured evidence, the five rules, and the two stated limits of the evidence. It is the authority; this plan is its argument.

## Global Constraints

- **No em-dashes anywhere**: code, comments, doc text, commit messages, template copy.
- **The six-verdict vocabulary is closed.** Dormancy is not a verdict and must never be published as one. It is a fact about this project's schedule.
- **A positive verdict means `Verified` or `UndeclaredButVerified`, and nothing else.** `DeclaredOnly` is not positive: it means we could not confirm anything.
- **`MeasurementRow::elapsed_ms` is `Option<u64>` and `None` means the metric budget expired.** Cost attribution MUST count `None` as the full metric budget, 60 s (`Budget::default().metric`; note `Budget::request` is the 30 s one, and the two are not the same number). Counting `None` as zero makes the most expensive endpoints look free, and they would never be relegated: that inverts the entire policy. The spec records that neither calibration run produced a single `None`, so this rule is a precaution and no test may assume the case is common.
- **Cost is the sum of per-metric elapsed for one endpoint in one run**, with the `None` rule above. This is the exact quantity the 60s threshold was calibrated against on the 2026-08-24 and 2026-08-26 runs; a different measure (wall clock, including politeness gaps) would need a fresh calibration and is out of scope.
- **An endpoint the prober failed on gets no strike.** `Sweep::failed_endpoints` counts endpoints with no observation at all; their cost is unknown, and an unknown cost is not evidence of an expensive one.
- **An operator hold overrides the machine in both directions**, including promotion. A slept endpoint is not probed and cannot be promoted by a verdict it never produces.
- **Never `git add -A`.** Stage files by name.
- **Reviewers and tests must not probe network endpoints.** Tests use wiremock or fixtures.
- **Commit messages end with:** `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- Default thresholds, from the spec: cost `> 60_000` ms, `2` strikes, cadence `7` days, wake grace `7` days.

**The rules `plan_sweep` implements**, in this order per endpoint:

1. `hold` is `Dormant` (any `until`): SKIP, `OperatorHold`.
2. `hold` is `Awake` and (`until` is `None` or `until > now`): PROBE.
3. `dormant_since` is `None`: PROBE.
4. `dormant_since` is set: PROBE only if `last_probed` is `None` or `last_probed + cadence_days <= now`, AND this endpoint is in the oldest `slice` of the due ones, where `slice = ceil(dormant_count / cadence_days)`, at least 1. Otherwise SKIP, `Automatic`.

Ordering the due set by `last_probed` ascending, then by `url` for determinism, is what spreads the first cohort: all 57 go dormant on one sweep, so without the slice they would all come due on one day and that day would cost the full 3.12 hours again.

**The rules `update` implements**, per endpoint in `endpoints`:

- Not in `outcomes` (skipped this sweep, or the prober failed on it): carry its state forward UNCHANGED. Do not touch `strikes`, `last_probed`, or `dormant_since`.
- In `outcomes` and `positive`: `strikes = 0`, `dormant_since = None`, `last_probed = now`, `last_cost_ms = Some(cost)`. This is promotion, and it happens even from dormancy.
- In `outcomes`, not positive, `cost_ms > thresholds.cost_ms`: `strikes += 1`, `last_probed = now`, `last_cost_ms = Some(cost)`, and if `strikes >= thresholds.strikes` and `dormant_since` is `None` then `dormant_since = Some(now)`.
- In `outcomes`, not positive, cost at or under the threshold: `strikes = 0`, `last_probed = now`, `last_cost_ms = Some(cost)`, `dormant_since` unchanged. A cheap silent endpoint is never dormant, which is the whole point of a cost-weighted policy.
- An endpoint carrying a hold keeps it untouched, and its strikes still accumulate underneath. That is deliberate: when a seven-day `Awake` grace lapses, the machine acts on what it observed during the grace rather than starting blind.
- Entries in `state` whose url is NOT in `endpoints`: kept only if they carry a `hold`, dropped otherwise. A registry that shrinks must not grow the state file forever, and a human decision must not vanish because a re-seed dropped a URL for a sweep.

Instants are compared as `xsd:dateTime` strings via a helper that parses to a `time`-free representation. Use `chrono`? NO: this crate has no date dependency and must not gain one. Parse the fixed `YYYY-MM-DDTHH:MM:SSZ` form that `--at` already validates (`main.rs:108 validate_instant`), convert to a day number plus seconds with a small pure function, and refuse anything else with an error naming the value. Reuse `validate_instant`'s shape; do not duplicate its regex loosely.

```rust
pub const DEFAULT_STATE: &str = "state/dormancy.toml";
pub fn read_state(path: &std::path::Path) -> anyhow::Result<State>;
pub fn write_state(path: &std::path::Path, state: &State) -> anyhow::Result<()>;
```

**The absent-versus-corrupt rule, and why it differs from `read_exclusions`.** `registry::read_exclusions` fails on a missing file because a missing exclusion list is a process that does not know which hosts asked to be left alone, and the harm of guessing is probing one of them. A missing dormancy state file is different in kind: it means no endpoint has strikes and none is dormant, which is exactly true on the first sweep after this stage and is the only way to bootstrap. So:

- Missing file: an empty `State`, logged at `info` naming the path.
- File present but unreadable, or present and unparseable: an ERROR that stops the sweep. Continuing would treat corrupt state as empty and then overwrite it, destroying every strike and every operator hold. That is the harm this direction guards.

`write_state` writes `<path>.partial` and renames onto `path`, creating the parent directory if needed. A rename is atomic on both platforms this runs on, so a killed sweep leaves either the old state or the new one and never a half-written file.

`outcomes_from` is a private function in `main.rs` with its own unit test, and it is where the `elapsed_ms` trap lives:

```rust
/// One outcome per endpoint the sweep actually probed.
///
/// `elapsed_ms` is `None` when the metric's budget expired, which is the MOST
/// expensive case there is: `emit.rs:59-65` declines to publish a zero for it
/// precisely because a zero would read as the fastest observation in the
/// dataset. Counting `None` as zero here would make the endpoints that burn a
/// full budget look free, and the policy would never relegate the 57 endpoints
/// it exists to relegate. It counts as the full metric budget.
fn outcomes_from(rows: &[MeasurementRow], probed: &[String], budget: Budget) -> Vec<Outcome> {
    let mut cost: BTreeMap<&str, u64> = probed.iter().map(|u| (u.as_str(), 0)).collect();
    let mut positive: BTreeMap<&str, bool> = probed.iter().map(|u| (u.as_str(), false)).collect();
    for row in rows {
        let Some(c) = cost.get_mut(row.endpoint.as_str()) else { continue };
        *c += row.elapsed_ms.unwrap_or(budget.metric.as_millis() as u64);
        if matches!(row.verdict, Verdict::Verified | Verdict::UndeclaredButVerified) {
            positive.insert(row.endpoint.as_str(), true);
        }
    }
    // An endpoint the prober failed on produced no row at all, so it has cost
    // 0 here and MUST NOT get an outcome: an unknown cost is not evidence of a
    // cheap one either. Only endpoints with at least one row are reported.
    probed.iter()
        .filter(|u| rows.iter().any(|r| &r.endpoint == *u))
        .map(|u| Outcome { url: u.clone(), cost_ms: cost[u.as_str()],
                           positive: positive[u.as_str()] })
        .collect()
}
```

### Task 3: Publish what the sweep did not probe

**Files:**

- Test: inline tests in `emit.rs` and `write.rs`, plus `prober/tests/end_to_end.rs`

**Interfaces:**
- Consumes: `dormancy::{Plan, Skipped, SkipReason}`.
- Produces:

```rust
pub struct DormancyFact { pub endpoint: String, pub dormant_since: String, pub reason: &'static str }
pub fn dormancy_quads(fact: &DormancyFact, run: &RunId) -> Vec<Quad>;
```

**The shape, and why it is a direct triple rather than a derived subject.** `DeclarationsRead` is already published as a triple hung directly off the endpoint (`web/load_run.py:383` reads `endpoint: sw:declarationsRead ?read`), because it is one fact about the endpoint in this run rather than a measurement against a metric definition. Dormancy is the same kind of fact, so it takes the same shape and needs no derived subject:

```
<endpoint> sw:dormantSince "2026-08-26T09:54:07Z"^^xsd:dateTime <run> .
<endpoint> sw:dormancyReason "automatic" <run> .
```

`sw:dormancyReason` is a closed two-value vocabulary, `"automatic"` and `"operator-hold"`, and `SkipReason` is what produces it. It is a string literal and not an IRI for the same reason the verdict slugs are: the value is read by a template, and a reader of the n-quads should not have to dereference anything to know what it says.

The activity gains one more fact, beside `sw:maxCost` and `sw:concurrency`:

```
<activity> sw:dormantEndpoints "48"^^xsd:integer <run> .
```

So a run says how many endpoints it declined to probe, and a reader can tell a 495-endpoint sweep of a 543-endpoint registry from a 495-endpoint registry.

**Where the facts are written.** The chunk protocol from stage 1c-b4 writes a header, one chunk per endpoint as it finishes, then a footer. Dormant endpoints finish nothing, so their facts cannot ride a chunk. They go in the HEADER, which is written before any probing and already knows the plan. That also means a killed sweep still says which endpoints it was not going to probe, which is the honest thing for a partial run to say.

**Files:**
- Modify: `web/load_run.py`
- Test: `web/tests/test_load_run.py`, plus a new fixture `web/tests/fixtures/run-with-dormancy.nq`

**Interfaces:**

**THE TRAP, and it is the whole task.** `_maintain_current` drives off `_MEASURED_ENDPOINTS`, and for each such endpoint runs a template that DELETES every fact `current` holds about it and re-inserts from the run (`load_run.py:369-391`). A dormant endpoint has no measurements, so:

The existing measured template deletes by `dqv:computedOn` and `sw:notMeasuredOn` and the explicit `sw:declarationsRead` and `sw:currentRun` lines; it does not delete `sw:dormantSince`.

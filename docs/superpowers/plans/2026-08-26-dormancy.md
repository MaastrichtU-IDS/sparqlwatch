# Dormancy (admission policy) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop spending 90% of every sweep on 57 endpoints that have never answered, without ever presenting a stale verdict as a fresh one, on any route or in any representation.

**Architecture:** A pure decision module (`prober/src/dormancy.rs`) holds the policy. A machine-written TOML state file holds strikes, last-probed instants and operator holds; the sweep reads it to decide what to probe and, at the end, re-reads it under a short lock and applies its outcomes to what is on disk then, so an operator command issued during a 90 minute sweep is not overwritten. Each sweep publishes, in its own dedicated section of the run graph, which endpoints it did not probe and why. The web tier carries dormancy into the derived `current` graph behind a recency pointer of its own, and every route that can show a verdict says how old that verdict is.

**Tech Stack:** Rust (serde, toml, clap 4), Python 3.12 (pyoxigraph 0.5.9, FastAPI, jinja2), pytest, cargo test.

**Spec:** `docs/superpowers/specs/2026-08-19-sparql-endpoint-monitor-design.md`, section **Admission policy: dormancy**. That section carries the measured evidence, the five rules, and the two stated limits of the evidence. It is the authority; this plan is its argument.

**Revision history.** The first draft of this plan was reviewed twice before execution and both reviews found Criticals: eight in total, plus twenty three Majors. This revision incorporates all of them, and the notes marked **REVIEW** below record the ones that changed a decision rather than a wording, so an implementer does not reinstate them.

## Global Constraints

- **No em-dashes anywhere**: code, comments, doc text, commit messages, template copy.
- **The six-verdict vocabulary is closed.** Dormancy is not a verdict and must never be published as one. It is a fact about this project's schedule.
- **A positive verdict means `Verified` or `UndeclaredButVerified`, and nothing else.** `DeclaredOnly` is not positive: it means we could not confirm anything.
- **`MeasurementRow::elapsed_ms == None` contributes ZERO to an endpoint's cost.** **REVIEW: this reverses the first draft, which counted it as the full metric budget.** `None` has three producers in `prober/src/lib.rs` and only one of them spent any time: the endpoint-budget fill (`lib.rs:566`, "the metrics we never got to") and a probe kind with no implementation (`lib.rs:668`, "skipped before any request is built") both cost exactly nothing, and only metric-budget expiry (`lib.rs:750`) cost 60 s. Attributing 60 s to all three fabricates cost, and the failure mode is not hypothetical: add one `metrics.toml` entry whose `ProbeKind` has no probe and every endpoint in the registry gains 60 s of phantom cost per sweep, crosses a 60 s threshold, and goes dormant in two sweeps. That is the failure-weighted policy the spec explicitly rejects. Counting zero is also safe in the case that looks dangerous: an endpoint that blew the 600 s `Budget::endpoint` accumulated roughly 600 s of REAL elapsed in the metrics that did run, so it is over any threshold on measured time alone. The residual is that one lone metric-budget expiry with every other metric instant contributes nothing, which at a 60 s threshold with a strict `>` was never a strike anyway.
- **Cost is the sum of per-metric `elapsed_ms` for one endpoint in one run**, with the rule above. This is the exact quantity the 60 s threshold was calibrated against, and the spec records that all 399 calibration measurements published an `elapsedMs`, so the threshold is calibrated on present values only.
- **An endpoint the prober failed on gets no strike.** It produces no `MeasurementRow` at all (`lib.rs:437-455`), so it must produce no `Outcome`. An unknown cost is evidence of nothing.
- **An operator hold overrides the machine in both directions**, including promotion, and **an operator command issued while a sweep is running must survive that sweep's write-back**. The sweep runs for roughly 90 minutes; a read-modify-write of a snapshot taken at the start would silently destroy any hold set in between.
- **`update` must be idempotent in `now`.** Re-running one `--at` is this project's documented recovery (`web/load_run.py:9-18`), and a re-run that adds a second strike would relegate on the strength of a single sweep.
- **Never `git add -A`.** Stage files by name.
- **Tests must not probe network endpoints.** Use wiremock or fixtures.
- **Commit messages end with:** `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- Defaults, from the spec: cost `> 60_000` ms, `2` strikes, cadence `7` days, wake grace `7` days. All four are flags, and all four are validated at startup.

## What the reviews established about the existing code, so no task rediscovers it

- `web/queries/index.rq:52` and `endpoint_measurements.rq:112` **already select `?generatedAt` and `?newestGeneratedAt` per row**, and `endpoint_index.py` already builds full `EndpointMeasurements` objects. The per-row age needs NO query change. What the queries do need is the dormancy fields out of `current`.
- `EndpointMeasurements.newer_run_did_not_reach_this_endpoint` (`web/endpoint_measurements.py:135-170`) requires `not self.newest_finalised` as one of five conjuncts. A sweep that FINISHES and simply never probes an endpoint satisfies none of them, so no existing qualifier fires. On this site an absent qualifier asserts that the newest sweep reached this endpoint.
- `load_run._holds_endpoint_facts` (`web/load_run.py:1031-1044`) rests on "every quad `emit_header` and `emit_footer` write has the run's activity for a subject". Endpoint-subject quads in the header break it, and the consequence is that a header-truncated file loads whole, wins the newest-run aggregate with no terminator, and silences unfinished-run detection for the whole site.
- `_maintain_current` and `rebuild_current` iterate `sorted(measured | sampled)` (`load_run.py:654`, `:807`). A dormant-only endpoint is in neither set, so there is no per-endpoint update for it to ride.
- `_advance` (`load_run.py:490`) governs `sw:currentRun` and `sw:currentSampleRun` only. A third family of facts with no pointer advances by load order.
- `tests/test_about.py:564-583` pins the sentence "nothing yet stops the dead being re-probed on every sweep" in `prober/README.md`, and its docstring says: "when the dead stop being re-probed, this claim stops being true and the page has to change." This is that stage.

pub const DEFAULT_COST_MS: u64 = 60_000;
pub const DEFAULT_STRIKES: u32 = 2;
pub const DEFAULT_CADENCE_DAYS: u64 = 7;
pub const DEFAULT_GRACE_DAYS: u64 = 7;
pub const STATE_VERSION: u32 = 1;

/// All four policy numbers in one value. `grace_days` is here and not a bare
/// constant so `wake` cannot hard-code a number the operator can change on
/// every other threshold.
pub struct Thresholds {
    pub cost_ms: u64,
    pub strikes: NonZeroU32,
    pub cadence_days: NonZeroU64,
    pub grace_days: NonZeroU64,
}
impl Default for Thresholds { /* the constants above */ }

/// An operator's decision. `Dormant` carries NO expiry: a hold the policy
/// ignores must not be representable, and rule 1 never reads an expiry, so a
/// malformed one on a Dormant hold would never be parsed and never detected.
pub enum Hold {
    Awake { reason: String, until: Option<String> },
    Dormant { reason: String },
}

pub struct EndpointState {
    pub url: String,
    pub strikes: u32,
    pub last_probed: Option<String>,
    pub last_cost_ms: Option<u64>,
    pub dormant_since: Option<String>,
    pub hold: Option<Hold>,
    /// The reason of a lapsed `Awake` hold, kept after `update` clears it, so
    /// `list` can still say a person intervened and when it ran out.
    pub lapsed_hold: Option<String>,
}

pub struct State { pub version: u32, pub updated_at: Option<String>, pub endpoint: Vec<EndpointState> }
impl State {
    pub fn empty() -> State;
    /// Validates `version` AND every instant-shaped field, naming the field.
    pub fn parse(toml_text: &str) -> anyhow::Result<State>;
    pub fn render(&self) -> String;
    pub fn get(&self, url: &str) -> Option<&EndpointState>;
}

pub enum SkipReason { Automatic, OperatorHold }
pub struct Skipped {
    pub url: String,
    /// `Option`, because an endpoint an operator slept was never automatically
    /// relegated and has no such instant. Emitting an empty xsd:dateTime into
    /// an immutable run graph is the failure this Option prevents.
    pub dormant_since: Option<String>,
    pub reason: SkipReason,
}
pub struct Plan { pub probe: Vec<String>, pub skipped: Vec<Skipped> }

pub fn plan_sweep(state: &State, endpoints: &[String], now: &str, thresholds: &Thresholds)
    -> anyhow::Result<Plan>;

pub struct Outcome { pub url: String, pub cost_ms: u64, pub positive: bool }
pub fn update(state: &State, endpoints: &[String], outcomes: &[Outcome], now: &str,
              thresholds: &Thresholds) -> anyhow::Result<State>;
pub fn wake(state: &State, url: &str, reason: &str, now: &str, permanent: bool,
            thresholds: &Thresholds) -> anyhow::Result<State>;
pub fn sleep(state: &State, url: &str, reason: &str, now: &str) -> anyhow::Result<State>;

**`plan_sweep`, per endpoint, in this order:**

1. `hold` is `Dormant`: SKIP, `OperatorHold`, carrying `dormant_since` as it stands (which `sleep` set).
2. `hold` is `Awake` and (`until` is `None` or `day(until) >= day(now)`): PROBE.
3. `dormant_since` is `None`: PROBE.
4. `dormant_since` is set: PROBE if `day(now) - day(last_probed) >= cadence_days` AND this endpoint is in the oldest `slice` of the due set. Otherwise SKIP, `Automatic`.

**Two things rule 4 gets right that the first draft did not.**

- **Compare DAY NUMBERS, never full instants.** REVIEW: `last_probed + cadence <= now` on full instants drifts. With `last_probed = 2026-09-02T19:45:03Z` and a sweep at `2026-09-09T19:30:00Z`, fifteen minutes early, the endpoint is not due and slips to day eight, and every early start pushes the whole cohort out again. Unit-test that case beside the leap day.
- **`slice` counts only the endpoints rule 4 governs**: present in `endpoints`, `dormant_since` set, and no effective hold. REVIEW: counting every entry with `dormant_since` inflates it, because `update` lets strikes accumulate under a hold by design, so a pinned-awake endpoint is both dormant and probed every sweep. With 57 automatic and 100 pinned-awake, `ceil(157/7) = 23` probes 23 of the real 57 per sweep, rotating the set in three days instead of seven and cutting the saving by roughly 2.5x.

`slice = ceil(governed_count / cadence_days)`, at least 1. Ordering the due set by `last_probed` ascending then `url` is what spreads the first cohort: all 57 relegate on one sweep and would otherwise all come due on one day, which costs the full 3.12 hours again. A due-but-unsliced endpoint keeps its old `last_probed`, so it sorts ahead of everything probed since and climbs into the next slice; it cannot starve.

**`update`, per endpoint in `endpoints`:**

0. **Idempotence gate, first.** If the endpoint has a `last_probed` and `day(now) <= day(last_probed)`, carry it forward unchanged and ignore any outcome for it. REVIEW: without this, re-running one `--at`, which `load_run.py:9-18` documents as the recovery, turns one sweep's strike into two and relegates against spec rule 1.
1. Clear a lapsed `Awake` hold: if `hold` is `Awake` with `until` and `day(until) < day(now)`, set `hold = None` and `lapsed_hold = Some(reason)`. REVIEW: a hold left in place forever makes `list` report a hold that does nothing, and keeps the entry alive after the registry drops it.
2. Not in `outcomes`: carry forward unchanged. Do not touch `strikes`, `last_probed` or `dormant_since`.
3. In `outcomes` and `positive`: `strikes = 0`, `dormant_since = None`, `last_probed = now`, `last_cost_ms = Some(cost)`. Promotion, and it happens from dormancy.
4. In `outcomes`, not positive, `cost_ms > cost_ms` threshold: `strikes += 1`, `last_probed = now`, `last_cost_ms = Some(cost)`, and if `strikes >= strikes` threshold and `dormant_since` is `None` then `dormant_since = Some(now)`.
5. In `outcomes`, not positive, cost at or under the threshold: `strikes = 0`, `last_probed = now`, `last_cost_ms = Some(cost)`, `dormant_since` unchanged.
6. A `Dormant` hold suppresses rules 3 to 5 entirely, since such an endpoint is never probed and never has an outcome. An `Awake` hold does not: strikes accumulate underneath, so when a grace lapses the machine acts on what it observed during the grace rather than starting blind.
7. Entries whose url is not in `endpoints`: kept only if they carry a live `hold`, dropped otherwise.
8. Duplicate urls in `outcomes` are an error, not two strikes.

`updated_at` is set to `now` on every `update`, `wake` and `sleep`. Task 2 uses it.

**The instant helper.** Private, pure, and it refuses anything that is not `YYYY-MM-DDTHH:MM:SSZ`, which is the form `main.rs:108 validate_instant` already requires. It yields a proleptic Gregorian day number. Do NOT add a date dependency to this crate. Its own unit tests cover a leap day (`2028-02-29`), a year boundary, and the early-start case above.

pub const DEFAULT_STATE: &str = "state/dormancy.toml";
/// The state as it is on disk. **Fails closed** on a missing file.
pub fn read_state(path: &Path) -> anyhow::Result<State>;
/// Re-read under an exclusive lock, apply `f` to what is on disk NOW, write,
/// release. The closure is what keeps a 90 minute sweep from clobbering an
/// operator command issued while it ran.
pub fn merge_state<F>(path: &Path, f: F) -> anyhow::Result<State>
where F: FnOnce(&State) -> anyhow::Result<State>;
/// Create an empty state file, refusing to overwrite one. The explicit
/// bootstrap that `read_state`'s fail-closed rule requires.

**REVIEW: a missing file FAILS, and this reverses the first draft.** The first draft made a missing file an empty state, reasoning only about the bootstrap. `registry.rs:355-373` documents the trap that reasoning walks into, for this exact kind of path: `DEFAULT_STATE` is resolved against the WORKING DIRECTORY, so a prober started from `/app` instead of `/app/prober`, or with a volume not mounted, names a file that is not there. Under the first draft's rule that deployment logs one `info` line, plans a full 543-endpoint sweep, ignores every operator `sleep`, and then CREATES the parent directory at the wrong path, so the divergence is permanent and silent and repeats every sweep. So: a missing file is an error naming the path, saying a relative path is resolved against the working directory, and naming `dormancy init` as the bootstrap. Corrupt or unreadable is an error for the reason the first draft gave: treating corrupt state as empty and then overwriting it destroys every strike and every hold.

**REVIEW: the write is a merge, not a write-back.** The 2026-08-24 sweep took 1h26m21s. A sweep that reads state at 19:45 and writes back at 21:11 destroys a `dormancy sleep` that landed at 20:10, which violates the Global Constraint that an operator hold overrides the machine. `merge_state` re-reads inside a short exclusive lock and applies the sweep's outcomes to THAT, so a hold set during the sweep is in the state the outcomes are applied to. Outcomes are per-endpoint deltas and holds are independent fields, so the merge is well defined.

The lock is a sibling `<path>.lock` created with `create_new` (the same `O_EXCL` idiom `write.rs:127` uses), held only across re-read plus write, which is milliseconds. It is NOT held for the sweep: a 90 minute lock would block the operator command it exists to protect. A lock that cannot be taken is an error naming the file and saying a stale one can be removed by hand; `dormancy wake`, `sleep` and `init` take the same lock.

**Files:**

**REVIEW: a section of its own, NOT the header. This reverses the first draft.** The first draft put dormancy facts in the header so a killed sweep would still say what it was not going to probe. That benefit is real and it is also what breaks the file format. `load_run._holds_endpoint_facts` (`load_run.py:1031-1044`) distinguishes a run's own metadata from facts about endpoints by testing whether every subject is the activity, and its docstring states the premise: "Every quad emit_header and emit_footer write has the run's activity for a subject." Endpoint-subject quads in the header make a header-truncated file one that parses, holds endpoint facts, and has no terminator, so `_quads_to_the_last_terminator` loads it whole; that graph then carries the store's greatest `prov:generatedAtTime` with no `sw:emission`, wins the newest-run aggregate in both readers, and **silences unfinished-run detection for every endpoint on the site**. It also breaks `emit.rs`'s own chunk invariants, since `EndpointFacts` makes "every fact about an endpoint is in one chunk" the property that makes the duplicate-subject pre-scan complete.

So dormancy is a fourth section, written after the header and before the first chunk, ending in its own terminator:

```
<endpoint> rdf:type dcat:DataService <run> .
<endpoint> sw:dormantSince "2026-08-26T09:54:07Z"^^xsd:dateTime <run> .   # omitted when None
<endpoint> sw:dormancyReason "automatic" <run> .
...one group per dormant endpoint...
<activity> sw:dormantEndpoints "48"^^xsd:integer <run> .                   # the terminator
```

Four properties this shape has to keep, each from a rule the codebase already states:

1. **The endpoint is typed here.** `emit.rs:536-545` types every endpoint inside its own chunk because "a reader of a truncated file may hold this chunk and not the one that typed the endpoint". A dormant endpoint has no chunk, so its type belongs in this section or it has none anywhere in the run graph.
2. **The count is the terminator, and it comes last.** `emit.rs:18-23` makes ordering a rule: no fact family publishes its own summary before the things it summarises, which is why `sw:failedEndpoints` is in the footer. The count both summarises the section and closes it.
3. **The terminator's subject is the activity.** `load_run._is_terminator_line` matches the predicate AND requires `urn:sparqlwatch:activity:` in subject position as a second anchor. A terminator on any other subject is not recognised.
4. **The count is published even when it is zero**, and the section is then just its terminator. A reader distinguishing "nothing was dormant" from "this run predates dormancy" needs the fact present. REVIEW: the first draft's test claimed the web queries treat its absence as the older shape; nothing in this plan reads the count, so state plainly that it is published for a reader of the n-quads and that no query consumes it yet.

`docs/design/section-terminators.md` is embedded at compile time and pinned by a test at the bottom of `emit.rs`; it gains the fourth terminator, and `load_run._TERMINATOR_PREDICATES` gains it in Task 6.

### Task 6: Carry dormancy into `current`, behind a pointer of its own

**Files:**

- Test: `web/tests/test_load_run.py`, plus fixtures `run-with-dormancy.nq`, `run-promotes-the-dormant.nq`, `run-measures-and-declares-dormant.nq`

**REVIEW: dormancy needs a THIRD POINTER. Both reviews raised this independently and it is the largest change from the first draft.** The first draft copied `sw:dormantSince` and `sw:dormancyReason` into `current` as bare endpoint triples. Four consequences, all reachable:

1. **Nothing guards recency.** `_advance` (`load_run.py:490`) governs `sw:currentRun` and `sw:currentSampleRun` only, so a third family with no pointer advances by LOAD ORDER. Load R1 (marks E dormant), then R2 (promotes E and clears it), then re-load R1, which `load_run.py:9-18` documents as the recovery: E is re-marked dormant while showing R2's fresh verdicts. That is the exact state `test_a_promoted_endpoint_loses_its_dormancy_facts` exists to forbid.
2. **Drift is undetectable.** `_DRIFTED_RUN_POINTERS` (`:319`) and `pointers_to_missing_runs` (`:564`) both ask which pointers name a run that no longer states their facts. With no pointer, dropping the run graph that declared an endpoint dormant leaves `current` asserting dormancy no run graph states, `LoadResult.drifted` empty, and `_opened_store` satisfied.
3. **`--check` compares nothing.** `_FACTS_FOR_ENDPOINT` (`:410`) matches measurement and not-measured subjects and `sw:declarationsRead`, so `check_current` prints "agrees with the run graphs" over a `current` holding a stale dormancy fact.
4. **The write never happens at all.** Both write loops iterate `sorted(measured | sampled)` (`:654`, `:807`), and a dormant-only endpoint is in neither set, so there is no per-endpoint `store.update()` for it to ride and the `if bodies:` gate at `:670` never fires. The first draft's `test_rebuild_current_reproduces_dormancy_from_the_run_graphs_alone` could not have passed.

So:

- A `sw:currentDormancyRun` pointer per dormant endpoint, written and gated by `_advance` exactly like the other two, with its own `_newest_per_endpoint` entry.
- `_DORMANT_ENDPOINTS` query, and both write loops iterate `measured | sampled | dormant`.

@property
def newest_sweep_did_not_probe_this_endpoint(self) -> bool:
    """A newer run FINISHED and deliberately did not ask this endpoint.
